# Chapter Quizzes & Mastery Wiring

Fixes and unifies the two quiz surfaces on the learning page
(`/learning/[pathId]/[videoIndex]`). Done in two phases.

## Background — two quiz systems

1. **Chapter quizzes** (per video segment) — generated by
   `VideoChunkingService` when a video is chunked, surfaced inline per chapter
   via `ChapterQuizModal`.
2. **Whole-video adaptive quiz** (IRT) — `QuizEngineService` / `/api/quiz`,
   surfaced by the "mastery quiz" card, with Item Response Theory difficulty,
   `ConceptMastery`, and FSRS spaced-repetition.

## Phase 1 — chapter quizzes generate real MCQs

**Bug fixed:** `VideoChunkingService._generate_quiz` called the **async**
`question_service.generate_question(...)` **without `await`**, so it always
discarded the coroutine and fell back to a single hard-coded free-text question.
Chapter quizzes never actually produced an AI question.

**Fix** (`backend/services/video_chunking_service.py`):
- New `async _generate_mcqs(chapter_title, content, key_concepts)` — generates
  **up to 3 real multiple-choice questions** from the chapter's learning
  objective + summary + key concepts via Claude (`claude-sonnet-4-6`), with the
  same prompt-injection guard used elsewhere (untrusted content in an isolated
  block). Malformed questions (not exactly one correct option) are dropped.
- `_generate_quiz` now runs it via `asyncio.run(...)` (safe — chunking runs in a
  plain BackgroundTask thread with no running loop). The free-text question
  remains only as a **last-resort** fallback when Claude yields nothing, so a
  chapter is never left with zero questions.
- Options stored as `[{"text", "correct"}]` — the shape `ChapterQuizModal`
  already reads.

## Phase 2 — unify mastery + reconcile the UI

**Mastery/FSRS wiring** (`save_progress` → `_update_concept_mastery`):
- A chapter-quiz result now updates `ConceptMastery` for each of the chapter's
  `key_concepts`, using the same upsert logic as the IRT engine
  (`concept_id` == concept name). Pass bar = **score ≥ 60%**; a concept is
  `is_mastered` at ≥ 80% accuracy. Previously chapter quizzes wrote only to
  `ChapterProgress.quiz_score` and never advanced mastery.
- **Failing** a chapter quiz enqueues one dedup'd `FSRSCard`
  (`source_type="chapter_quiz"`, `source_id=chunk.id`) so the chapter resurfaces
  in the spaced-repetition queue — the same queue the IRT engine feeds.
- Both are best-effort: a failure here never blocks progress saving.

**UI reconciliation** (`frontend/pages/learning/[pathId]/[videoIndex].tsx`):
- The standalone quiz card is relabelled **"Whole-video mastery check"** /
  "Start mastery quiz", framed as the step *after* the inline chapter checks, so
  the two surfaces read as sequential, not duplicate.
- The adaptive quiz is now **concept-scoped** to the video (passes
  `concept={derivedConcepts[0].name}` to `QuizModal`) instead of drawing from the
  general pool by topic name only.

## Phase 3 — fix the endless "generating…" loop + graceful failure

**Root cause:** `POST /api/chunks/{id}/generate` passed the **request-scoped** DB
session into the FastAPI BackgroundTask. FastAPI closes that session when the
202 returns, so the background `chunk_video` died silently on a closed session —
chunks were never written, and the frontend polled `GET /api/chunks` forever
(only bailing on a blind ~3.5-min timer).

**Fix:**
- New `VideoChunkingService.chunk_video_task(youtube_id, video_db_id)` opens its
  OWN session via `_get_session_factory()` (never the request's) and records the
  outcome on the Video row.
- Two new `Video` columns — `chunk_status` (None|processing|ready|failed) and
  `chunk_error` — added via `_SCHEMA_PATCHES` (auto-applied on boot, no manual
  migration).
- `generate` sets `chunk_status="processing"` (clearing any prior error) before
  returning, and dispatches the new task. `GET /api/chunks/{id}` now reports the
  real lifecycle: `ready` (with chunks) / `processing` / `failed` (with `error`).
- Frontend `ChaptersList` polls only while `processing`, **stops on `failed`**
  and shows the error with a "Try again" button (no more infinite spinner). Cap
  ~4 min as a last-resort safety, with an honest message.

Tests: `test_chunk_video_task_records_failed_status` /
`_records_ready_status` (DB-backed, skip without Postgres).
